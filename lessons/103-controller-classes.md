## 📘 Урок 103. Классы контроллеров — Home и Listings

Итак, теперь наш роутер способен принимать маршруты в таком виде.

У нас уже создан **HomeController**,
и у него есть метод **index**, который сейчас просто делает `die` и выводит текст.

В этом видео я хочу взять **всё, что сейчас находится в файлах-контроллерах**,
перенести это в **классы**,
и сделать так, чтобы всё работало **точно так же, как раньше**.

После этого мы сможем **удалить всю папку listings**, потому что она нам больше не понадобится.

Также мы создадим **отдельный ErrorController**,
вместо того чтобы иметь отдельный файл под каждый HTTP-статус.

---

### 🏠 Обработка главной страницы (Home)

Начнём с главной страницы.

У нас уже есть своего рода **скелет класса**.

Мы используем базу данных в HomeController,
потому что на главной странице мы получаем список вакансий.

Давайте откроем `Home.php`.

Наша задача — **перенести всю логику из старого контроллера в метод `index`**.

Так как мы используем базу данных,
нам нужно добавить:

```php
use Framework\Database;
```

Это первый шаг.

Теперь создание объекта базы данных я перенесу **в конструктор**,
чтобы при создании HomeController база автоматически подключалась.

Мы хотим, чтобы `$db` был **свойством класса**,
поэтому выше конструктора объявляем:

```php
protected $db;
```

А в конструкторе пишем:

```php
$this->db = new Database($config);
```

Теперь объект базы данных доступен **в любом методе контроллера**.

Возвращаемся в `Home.php`,
берём всю старую логику,
удаляем её оттуда
и **вставляем в метод `index`**.

Единственное, что нужно изменить —
`$db` теперь становится `$this->db`.

Мы выполняем запрос, получаем данные
и загружаем представление, передавая туда `listings`.

Сохраняем и перезагружаем страницу —
**всё работает**.

Обратите внимание, **насколько это чище**, чем было раньше.

Я специально не начинал с такого подхода,
потому что для многих это было бы слишком сложно.

Я предпочитаю **постепенные, инкрементальные изменения**,
чтобы вы понимали, **что именно происходит**.

С главной страницей закончили.

### 📄 Контроллер Listings

Теперь нам нужен **ListingController**.

В этом контроллере мы будем:

* получать список вакансий
* создавать вакансии
* удалять
* обновлять
  и вообще делать **весь CRUD**

Файл `home.php` нам больше не нужен —
можем **удалить его**,
и всё всё равно будет работать.

---

### 🆕 Создание ListingController

В папке `controllers` создаём файл:

```
ListingController.php
```

Всё почти так же, как в HomeController:

* namespace
* `use Database`
* конструктор

Я просто **копирую HomeController**
и вставляю его в новый файл.

Меняю имя класса на `ListingController`.

Нам **не нужно ничего подключать вручную**,
потому что:

* автозагрузчик уже работает
* роутер сам создаёт экземпляр контроллера

---

### 🛣 Добавление маршрута `/listings`

Добавляем маршрут:

```
/listings → ListingController@index
```

Сохраняем и перезагружаем.

Пока будет ошибка `ListingController not found`,
потому что метод ещё не реализован.

---

### 📋 Метод index в ListingController

Конструктор и база данных остаются такими же.

В методе `index` логика почти та же,
но **без ограничения LIMIT**,
потому что на странице listings мы показываем **все вакансии**.

Сохраняем, перезагружаем —
**работает**.

---

### ➕ Метод create

Теперь, когда мы кликаем на `/create`,
мы хотим вызывать метод `create`.

Добавляем маршрут:

```
/listing/create → ListingController@create
```

Создаём метод:

```php
public function create()
```

В старом `create.php` была только загрузка представления —
мы просто переносим этот код.

Сохраняем, открываем `/listing/create` —
**страница работает**.

---

### 🔍 Страница одной вакансии (show)

Сейчас при клике на вакансию ничего не работает,
потому что маршрута ещё нет.

Мы можем **удалить старые файлы**:

* `listings/create`
* `listings/index`

Главная, список и create всё ещё работают.

Теперь добавляем маршрут:

```
/listing → ListingController@show
```

(позже мы добавим ID в маршрут, но пока без него)

Метода `show` ещё нет, поэтому будет ошибка.

---

### 🧠 Метод show

Создаём метод:

```php
public function show()
```

Открываем старый `show.php` и смотрим, что там:

* получаем `id`
* формируем массив параметров
* выполняем подготовленный запрос
* загружаем представление

Копируем эту логику в метод `show`,
и снова меняем `$db` на `$this->db`.

Сохраняем и перезагружаем —
**всё работает**.

---

Теперь можно **удалить всю папку `controllers/listings`** —
она больше не нужна.

Проект стал значительно чище и аккуратнее.
