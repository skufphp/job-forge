## Урок 104. Класс ErrorController

Итак.

Теперь мы создадим **новый контроллер для ошибок**.

Сначала хочу упомянуть одну вещь: в прошлом видео я забыл добавить комментарии к методам контроллеров, поэтому позже я их дописал. Например:

* показать все объявления
* показать форму создания объявления
* показать одно объявление
* а в HomeController — просто показать последние объявления

Мне нравится поддерживать код чистым и понятным с помощью комментариев.

---

### Текущая проблема с обработкой ошибок

На данный момент у нас есть **папка error**, в которой находится файл `404.php`, который просто загружает представление.

Но это **не тот подход**, который я хочу использовать.

* Я хочу быть **последовательным** и использовать **классы**
* Я не хочу создавать **отдельную папку для каждого типа ошибки**

---

### Создание ErrorController

Поэтому давайте **полностью удалим папку `error`**
И создадим новый файл:

```
ErrorController.php
```

Я просто скопирую код из `HomeController` и вставлю его сюда.

Теперь:

* Мы **не используем базу данных**, поэтому `use Database` можно удалить
* Конструктор нам тоже не нужен — удаляем его
* Меняем имя класса на `ErrorController`

---

### Методы для разных типов ошибок

Теперь мы создадим **отдельные методы для разных ошибок**.

#### 404 — Not Found

Добавим комментарий:

> 404 not found error

Переименуем метод в `notFound`.

Метод будет принимать `$message`, но мы зададим **сообщение по умолчанию**:

```
Resource not found
```

Зачем это нужно?

* Если сообщение не передано — будет стандартное
* Если, например, мы работаем с объявлениями, можно передать:

    * `Listings not found`
    * `Listing not found`

---

Теперь:

* Удаляем лишний код
* Оставляем загрузку представления

Перед загрузкой представления мы:

1. Устанавливаем HTTP-статус:

   ```
   404
   ```
2. Загружаем представление `error`
3. Передаём туда:

    * `status` → `404`
    * `message` → текст ошибки

---

### Добавим ещё одну ошибку — 403 Unauthorized

Скопируем метод и создадим второй:

#### 403 — Unauthorized

Комментарий:

> 403 unauthorized error

Изменения:

* Имя метода: `unauthorized`
* Сообщение по умолчанию:

  ```
  You are not authorized to view this resource
  ```
* HTTP-код: `403`
* Загружаем то же самое представление `error`
* Передаём `status` и `message`

---

### Представление ошибок

Теперь перейдём в папку `views`.

Там сейчас есть папка `error` с файлами `403.php` и `404.php`.

Мы **не хотим создавать отдельный файл под каждую ошибку**, поэтому:

1. Создаём новый файл:

   ```
   error.view.php
   ```
2. Копируем HTML из `404.php`
3. Вставляем его в `error.view.php`
4. **Удаляем папку `error` целиком**

---

### Обновление error.view.php

Теперь, так как мы передаём данные в представление:

* Вместо статичного текста выводим:

    * `<?= $status ?>`
    * `<?= $message ?>`

Верхний и нижний баннеры мы убираем — они здесь не нужны.

---

### Статические методы

Есть ещё одна важная вещь.

Мы **не хотим каждый раз создавать объект ErrorController**, потому что:

* Нам не нужно несколько экземпляров
* Это просто набор утилитарных методов

Поэтому:

```php
public static function notFound()
public static function unauthorized()
```

---

### Автозагрузка

Файл `ErrorController.php` будет **автоматически загружаться**, потому что:

* Он находится в `app`
* Наш автозагрузчик настроен на `app` и `framework`

---

### Использование ErrorController в Router

Теперь идём в `Router.php`.

Раньше у нас был метод `error()`, который:

* устанавливал код
* загружал представление

Теперь он **нам не нужен**.

Мы можем просто вызвать:

```php
ErrorController::notFound();
```

Поскольку метод статический, используем **оператор разрешения области видимости `::`**.

---

### Подключение пространства имён

Если мы попробуем открыть несуществующий маршрут, например:

```
/test
```

Мы получим ошибку:

> ErrorController not found

Почему?

Потому что контроллер находится в пространстве имён `App\Controllers`.

Добавляем в Router:

```php
use App\Controllers\ErrorController;
```

Теперь всё работает:

* Возвращается **404**
* Сообщение: *Resource not found*

---

### Результат

Теперь у нас есть:

* Чистый **ErrorController**
* Один универсальный `error.view.php`
* Нет лишних папок и файлов
* Централизованная логика обработки ошибок
* Код стал заметно чище и аккуратнее
