## 📘 Урок 102. Рефакторинг роутера под классы контроллеров

Итак, ребята.

Теперь мы будем **рефакторить наш роутер**, потому что мы собираемся изменить подход:
наши контроллеры больше **не будут просто отдельными PHP-файлами**, как сейчас.

Мы хотим иметь, например, **ListingsController** или **HomeController** — то есть **классы контроллеров** с методами, на которые мы сможем указывать напрямую.

Идея в том, чтобы **маршрут указывал не на файл**, а **на метод контроллера**.

---

### 🔁 Как это должно выглядеть

Чтобы показать, как это будет работать, представим следующий пример:

Мы пишем:

```
router->get('/', 'HomeController@index');
```

То есть:

* `/` — это URI
* `HomeController@index` — это **контроллер + метод**

Вместо того чтобы писать путь к файлу `controllers/home.php`,
мы хотим указывать **HomeController@method**.

Для этого нам нужно изменить (рефакторить) роутер так, чтобы он мог это обрабатывать.

---

### 🔧 Изменения в Router.php

Давайте зайдём в `router.php`.

Сейчас у нас есть метод `registerRoute`, который принимает путь к файлу контроллера.
Но теперь мы **не передаём путь к файлу**, мы передаём **action** — строку вида:

```
HomeController@index
```

Поэтому:

* переименовываем параметр `controller` в `action`
* используем `action` везде дальше

---

### ✂️ Разбор строки action

Нам нужно **разделить строку `HomeController@index` на две части**:

* имя контроллера
* имя метода

Для этого мы используем `explode`, потому что:

* у нас есть строка
* мы хотим превратить её в массив
* разделитель — символ `@`

Пример:

```php
$action = explode('@', $action);
```

Чтобы посмотреть, что получится, временно используем `inspect()` и `die()`.

После перезагрузки страницы мы увидим массив:

* первый элемент — `HomeController`
* второй элемент — `index`

---

### 📦 Используем list() (деструктуризация)

Теперь мы можем аккуратно извлечь значения:

```php
list($controller, $controllerMethod) = $action;
```

Это похоже на **деструктуризацию в JavaScript**.

Проверяем:

* `$controller` → `HomeController`
* `$controllerMethod` → `index`

---

### 🗂 Добавляем в массив маршрутов

Теперь:

* в массив маршрутов добавляется **имя контроллера**
* и **имя метода контроллера**

То есть роут теперь знает:

* какой контроллер
* какой метод вызывать

---

### 🚦 Обработка запроса маршрута

Теперь переходим к методу, который **обрабатывает запрос**.

Мы всё ещё:

* перебираем маршруты
* проверяем URI
* проверяем HTTP-метод

Но вместо `require` файла:

* мы будем **создавать экземпляр класса контроллера**
* и **вызывать метод**

---

### 🧭 Формирование полного имени класса

Контроллеры будут находиться в пространстве имён:

```
App\Controllers
```

Поэтому полное имя класса будет выглядеть так:

```php
App\Controllers\HomeController
```

Мы формируем его динамически, используя данные маршрута.

---

### 🧱 Создание экземпляра контроллера

Контроллер — это класс, значит мы делаем:

```php
$controllerInstance = new $controller;
```

Это может быть:

* HomeController
* ListingsController
* UsersController
* любой другой

Это часть **ядра нашего мини-фреймворка**, а не логики конкретного ресурса.

---

### ▶️ Вызов метода контроллера

Теперь вызываем нужный метод:

```php
$controllerInstance->$controllerMethod();
```

Если, например:

* маршрут `/listings`
* контроллер `ListingsController`
* метод `index`

То по факту выполнится:

```php
(new ListingsController())->index();
```

И вся логика этого маршрута будет находиться **в методе контроллера**.

---

### ❌ Ошибки и почему они появились

Если сейчас перезагрузить страницу, появится куча ошибок:

* `Undefined array key`

Причина в том, что старые маршруты **не используют формат `Controller@method`**.

Роутер ожидает строку с `@`, а получает просто путь к файлу.

Это нормально на этом этапе.

---

### 🏗 Создаём HomeController

Теперь создаём контроллер.

В папке `controllers` создаём файл:

```
HomeController.php
```

Используем **PascalCase** — это стандарт для классов.

Добавляем namespace:

```php
namespace App\Controllers;
```

Создаём класс:

```php
class HomeController
```

---

### ⚙️ Автозагрузка классов

Мы **не подключаем файлы вручную**, потому что:

* используется автозагрузка по PSR-4
* Composer сам загрузит класс по namespace

---

### 🧪 Проверка через constructor

Для проверки создаём `__construct()` и выводим сообщение:

```php
public function __construct()
{
    die('HomeController');
}
```

Перезагружаем страницу — видим сообщение.
Значит контроллер **успешно создаётся**.

---

### ▶️ Метод index()

Теперь создаём метод `index()`:

```php
public function index()
{
    die('HomeController@index');
}
```

И меняем маршрут на:

```
HomeController@index
```

Перезагружаем — видим сообщение.
Значит:

* маршрут работает
* метод контроллера вызывается

---

### ➕ Другие маршруты

Если мы добавим маршрут, например:

```
HomeController@create
```

И создадим метод `create()` —
он будет вызван при переходе по этому маршруту.

* в методы классов контроллеров
* и вернём приложение в полностью рабочее состояние
